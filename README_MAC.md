# Mac 本地 AI 隔空绘画

基于 [moizaiqbal40-ops/ai_virtual_painter](https://github.com/moizaiqbal40-ops/ai_virtual_painter) 改造，保留原 MIT 许可证和作者版权。摄像头图像、手部模型推理与绘画全部在本机运行，无账号、无收费 AI API、无图像上传。

## 启动

首次使用请先按根目录 README 安装环境和模型，然后在项目根目录执行：

```bash
./start.sh --foreground
```

也可以双击项目目录的 `Air Painter.app`。应用依赖旁边的项目目录和 `.venv`，请保持整个目录完整。Finder 和终端启动均通过 `run_app.py` 执行同一套环境检查。

需要由本地 `.app` 后台启动时：

```bash
./start.sh
```

启动器提供摄像头与“文稿”目录的用途声明。若将项目放在“文稿”目录，macOS 可能请求目录访问；权限由你在系统弹窗中批准。

首次启动由 macOS 请求摄像头权限，点击“允许”。如果被拒绝，在“系统设置 → 隐私与安全性 → 摄像头”允许 **Air Painter** 或当前启动应用，再重启。本项目提供带 `NSCameraUsageDescription` 的原生应用启动器，避免直接使用 Homebrew Python 时无法正常请求权限的问题。

程序初始为暂停。点击“开始”或按空格开始；按钮和颜色均可鼠标点击，也可伸出食指、中指，将食指尖悬停在目标上约 0.7 秒。每次悬停只触发一次，需要移开后才能再次触发。

界面默认中文，包括窗口标题、工具、颜色、手势状态、保存结果和分组完成提示；快捷键保持不变。使用 macOS 自带中文字体在本机渲染，并缓存文字图像，不下载字体、不联网。Pillow 已在原有虚拟环境和依赖锁定文件中，本次明确列为直接依赖。

手指绘画默认显示两层粒子特效：随画笔变色的闪光沿食指平滑轨迹散开，在约 0.4–0.75 秒内渐隐；细小的橙金色火星独立飞散、带短拖尾，受重力下落并逐渐冷却为橙红色，在约 0.5–0.85 秒内消失。画笔及形状预览都会显示；鼠标绘画、橡皮擦、捏合拖动和暂停不产生粒子。控制操作会清除残留火花和火星。特效只绘制在实时预览中，不写入画布或对象，也不包含在普通/透明 PNG 中；不会改变撤销、分组或图形移动。两种粒子合计最多 180 个。仍可用 G 开关分组，粒子不占用该快捷键。

## 使用

| 操作 | 方法 |
| --- | --- |
| 绘画 | 开始后，仅伸出食指，在画面中移动；允许拇指自然伸出 |
| 自由画笔 / 直线 / 矩形 / 椭圆 | 顶部工具按钮，或 P / L / R / O |
| 形状预览与确认 | 食指移动或鼠标按下拖动；抬笔 / 松开鼠标后确认 |
| 取消正在预览的形状 | X；已确认的形状用撤销删除 |
| 临时抬笔 | 握拳、伸出两指、张开手掌，或手离开画面 |
| 抓取 / 拖动 / 释放 | 开始后，在图形笔迹附近捏合拇指与食指，保持捏合移动，张开两指释放 |
| 多笔组成一个对象 | “分组”按钮或 G 开启分组；画完后“完成”按钮或 F 完成；再次按 G 关闭分组 |
| 开始 / 暂停 | “开始” / “暂停”按钮，或空格 |
| 红 / 绿 / 蓝及其他颜色 | 左侧色块或数字 1–7 |
| 撤销一整笔 | “撤销”，Z 或 U；最多保留 30 步 |
| 重做 | “重做”或 Y；重新绘画、擦除或清屏后清除重做分支 |
| 橡皮擦 / 返回画笔 | 左侧“橡皮擦”或 E；橡皮擦模式选择颜色自动回到画笔，形状模式换色保留工具 |
| 清屏 | “清空”或 C；清屏后仍可撤销恢复 |
| 保存 | “保存 PNG”或 S，保存到项目内 `paintings/` |
| 透明背景 PNG | “透明 PNG”或 T，保存带 Alpha 通道的 PNG |
| 黑底 / 白底普通 PNG | 顶部“背景”按钮或 B 切换；按 S 保存，不影响透明导出 |
| 隔空 / 鼠标绘画 | M 切换输入；鼠标模式下按住左键在画布区域拖动 |
| 调整笔宽 | + / -，范围 3–55 像素 |
| 调整平滑 | [ / ] 每次调整 0.05，或点击顶部“平滑”按钮切换常用系数 |
| 时间模式 / 返回绘画 | 底部“时间 TIME”按钮或 K |
| 花朵时间演示 | 底部“花朵演示”按钮或 J；进入 TIME，保留当前进度 |
| 回到花苞 | TIME 中点击“回到花苞”或 N；捏合后重新张开 |
| 骨架显示 | H |
| 退出 | 点击左下角“退出”；也可按 Q、Esc、Ctrl+Q 或关闭窗口 |

普通保存为 1100×720 黑底或白底 PNG（“背景”按钮选择）；透明导出为同尺寸的 RGBA PNG，空白和擦除区域透明，边缘保留抗锯齿。这两种导出均只包含绘画，不包含摄像头画面、骨架或操作栏。文件名含微秒，避免短时间内连续保存覆盖。保存失败时提示检查剩余空间和目录权限，画布内容保留；双击启动时详细原因写入 `.cache/run.log`，前台启动时显示在终端。

形状从拖动起点到当前位置实时预览，不将途中经过的边框写入永久画布；确认后算一笔，可以整体撤销和重做。矩形和椭圆使用两个角确定边界；椭圆的宽高相等时为圆。只是点击而未拖动不会生成形状。取消预览不影响已有绘画和重做历史。隔空模式下握拳、伸出两指或手离开画面都会确认当前形状。

退出时自动将笔宽、平滑系数、颜色、工具、输入模式、骨架开关和导出背景保存到项目内 `settings.json`。下次启动恢复设置，但画布保持空白、程序保持暂停；这项功能不自动保存或加载画作。配置文件缺失、损坏或值不合法时使用默认值，保存采用临时文件原子替换，失败时保留上一份有效配置。

临时恢复默认值并禁止读写设置：

```bash
./start.sh --foreground --no-settings
```

指定独立配置文件可使用 `--settings /path/to/settings.json`。显式传入 `--smoothing` 时覆盖保存的平滑系数，并在正常退出后保存该值。“平滑”按钮按 0.20 / 0.35 / 0.45 / 0.65 / 1.00 循环，系数越小越平滑、延迟越明显。

橡皮擦沿用食指移动或鼠标拖动控制；需先选择橡皮擦，不使用张开手掌自动擦除，避免误操作。擦除宽度为当前笔宽的 3 倍，最少 18 像素。擦除和清屏都能撤销、重做。预览使用独立透明度层，擦除后重新显示摄像头画面。

完全无需摄像头的鼠标绘画：

```bash
./start.sh --foreground --no-camera
```

此模式不会申请摄像头权限、打开摄像头或创建模型实例。仍需点击“开始” / 按空格开始，再按住鼠标左键绘画。`M` 在此模式保持鼠标输入。相同参数可用于普通 `start.sh` 的 `.app` 启动方式。

当前使用单手绘画，避免双手遮挡或左右手标签切换造成误连线。建议把手掌朝向摄像头、食指向上，光线充足。手势判断复用了原项目的指尖与指关节高低比较；侧握、倒置或严重遮挡时准确率可能下降。

### 单手开合控制与花朵演示

点击底部“花朵演示”或按 J，进入 TIME。先捏合拇指和食指约 0.1 秒，花朵回到花苞；逐渐张开两指时花瓣同步展开，完全张开时刚好盛开。重新合拢两指可倒放回花苞。手指开合幅度保持不变时，花朵保持不变；左右或上下移动手部不会推进动画。已移除进度条、百分比和鼠标时间轴。

按 K 或点击“返回绘画”回到原画布；按 N 或点击“回到花苞”重置，随后捏合并重新张开。动画跟随手势开合幅度，不按固定时长独立播放。完全张开并稳定约 0.1 秒后会精确到达盛开终点，不会因平滑停在接近完成的位置。

TIME 复用 landmark 4 / 8 与手掌尺寸归一化，捏合沿用 0.28 / 0.46 滞回和 0.1 秒防抖；开始后用归一化两指间距从 0.28（捏合）到 1.15（充分张开）映射整个花朵动画，使用现有 EMA 平滑及微小间距抖动过滤。捏合释放阈值只用于识别捏合状态，不会提前结束展开动画。更远离摄像头、手掌缩放或平移不改变开合进度。

手部短暂丢失会冻结，恢复后的第一帧仍保持花朵状态；后续开合变化平滑响应。连续丢失约 0.65 秒后安全停止，需要先张开两指，再捏合开始。进入 TIME 时结束对象拖动，保留已画出的笔迹，取消尚未确认的形状预览。TIME 中绘画、对象拖动、编辑和 PNG 保存暂停；原绘画的开始/暂停状态保留。退出 TIME 后先抬笔，再伸食指恢复绘画，避免模式切换产生多余线条。

花朵用独立背景和花瓣图层，根据开合幅度计算每片花瓣的角度、形状和色彩，支持直接倒退；动画不写入用户画布、对象或撤销重做历史。当前花朵状态仅在本次运行中保留，不纳入 PNG 绘画导出。

直接启动演示：

```bash
./start.sh --foreground --time-demo
```

无需摄像头的静态花苞预览：

```bash
./start.sh --foreground --no-camera --time-demo
```

无摄像头模式不申请权限、不创建模型；没有鼠标时间轴，开合体验需使用摄像头。正常模式仍只追踪一只手，切换 TIME 不重新初始化摄像头或模型。没有新增依赖、浏览器运行环境或云端 API。当前界面见 [半开花朵](docs/images/flower-half.png)，测试与真人验收步骤见 [验证说明](docs/VERIFICATION.md)。

### 独立对象与捏合移动

默认每次连续绘画抬笔后成为一个独立对象，直线、矩形、椭圆确认后也是独立对象。五角星可以一笔完成；由多笔构成的图形，先按 G 开启分组，允许抬笔、换色、继续补画，完成后按 F。分组模式继续保持开启，下一笔开始下一个对象；按 G 可关闭。开始捏合抓取时，也会完成当前分组。

分组开启后显示当前组的笔画数。按 F 或点击“完成”后，整组显示绿色确认框、`已完成 #对象编号` 及“对象已完成”的明显提示；可以直接捏合任意一笔移动整组。食指保持伸出时不会立刻开始新笔画，先张掌或伸出两指抬笔，再伸食指即可绘制下一组。完成确认不会暂停程序，也不保存 PNG；PNG 仍用 S / “保存 PNG”。没有正在绘制的分组时会提示“没有待完成的分组”；分组关闭时不会把已有独立对象事后合并。

点击“开始” / 空格开始后，将拇指与食指的捏合点放在图形笔迹附近，保持约 0.1 秒即可抓取，出现黄色包围框；保持捏合移动，再张开拇指和食指约 0.1 秒释放。空心图形需要抓边缘，不能只捏在空白中心。多个图形重叠时，只抓取命中的最上层对象。未命中时保持捏合不会沿途抓到别的图形，需要先张开再捏合。

释放后可以再次捏合同一图形。要重新绘画，先张开手掌或伸出两指抬笔，再只伸出食指；释放时直接保持食指伸出会继续抬笔，避免留下多余线条。暂停、换工具、保存、切换输入及撤销会结束当前拖动。每次实际移动作为一个撤销步骤；只抓住但没有移动不会消耗历史或清除重做。

移动保留抓取偏移、原始像素和层级，不缩放、不改变颜色。拖动平滑使用当前 EMA 系数。手部短暂丢失会冻结，恢复后从当前位置重新设置抓取偏移；连续丢失约 0.65 秒后安全释放，需要张开两指后才能再抓取。单帧位置跳变超过 150 像素也会重新设置偏移，避免图形瞬移；快速大幅移动可能因此暂停一次。

对象及分组仅在当前运行中保存；PNG 导出保留移动后的绘画效果，但不会保存可重新编辑的对象工程。退出后画布仍为空。鼠标绘画生成相同对象；捏合移动需要切回隔空输入。本次没有增加鼠标拖对象工具。

算法与源码审计见 [DRAG_IMPLEMENTATION.md](DRAG_IMPLEMENTATION.md)。全部识别、命中检测和移动仍在本机执行，没有增加云端 API 或依赖。

平滑采用原项目 EMA 算法，改为保留浮点状态；抬笔、停止、换色、丢失追踪后重置，坐标突跳时自动断笔。希望更平滑时：

```bash
./start.sh --foreground --smoothing 0.3
```

系数在 (0,1]，越小越平滑但延迟越明显。初始默认 0.45，之后恢复保存的值。绘画窗口已打开时，请先退出再使用新的启动参数。

## 自动环境检查

启动脚本在首次安装时寻找 Python 3.11/3.12，创建独立 `.venv`，安装依赖和官方模型。后续启动检查 Python 版本、包版本、依赖关系、模型 SHA-256、摄像头权限，并通过 AVFoundation 实际打开摄像头。日常启动不联网；只有初次安装、依赖修复或模型缺失时下载。

这台 Mac 默认 Python 是 3.14，程序使用已安装的 Python 3.11.15，不修改系统 Python。验证环境为 Apple M1 Pro / ARM64、macOS 27.0。

| 依赖 | 固定版本 |
| --- | --- |
| MediaPipe | 0.10.32 |
| OpenCV contrib | 4.11.0.86 |
| NumPy | 1.26.4 |
| Pillow（中文文字渲染） | 12.3.0 |
| PyObjC AVFoundation | 11.1 |

使用 `opencv-contrib-python` 满足 MediaPipe 自身依赖，避免同时安装多个共享 `cv2` 名称的 OpenCV 包。`requirements.lock.txt` 固定了本机验证通过的全部间接依赖，适用于本机重装。

修复依赖或首次在新机器安装：

```bash
./setup.sh
```

需要 macOS 13+、Python 3.11/3.12 和 Xcode Command Line Tools。源码包不包含生成的 `.app`，`setup.sh` 在本机自动构建；单独重新构建使用 `./scripts/build-app.sh`。项目尚未在 Intel Mac 验证。

切换摄像头（先退出当前窗口）：

```bash
./start.sh --camera 1
```

诊断和测试（真实模型图片测试需先按根目录 README 下载官方测试图片）：

```bash
.venv/bin/python doctor.py
.venv/bin/python doctor.py --camera --report test-output/live_camera.json
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/test_model.py
.venv/bin/python scripts/test_ui.py
.venv/bin/python scripts/test_mouse_ui.py
.venv/bin/python scripts/test_shapes_ui.py
.venv/bin/python scripts/test_hand_shapes.py
.venv/bin/python scripts/test_drag_ui.py
.venv/bin/python scripts/test_exit_ui.py
.venv/bin/python scripts/test_group_done_ui.py
.venv/bin/python scripts/test_particles_ui.py
.venv/bin/python scripts/test_time_ui.py
```

`doctor.py --camera` 会读取 30 帧并执行本地模型。`test_model.py` 使用已下载到 `test-output/pointing_up.jpg` 的官方测试图片，验证真实推理、7 色绘画、清屏恢复和 PNG 保存。摄像头受 macOS TCC 控制；从不同宿主启动 Python 可能出现不同授权状态，当前推荐 `start.sh --foreground`。

`test_ui.py` 用官方图片代替摄像头输入，在真实 OpenCV 窗口中自动执行鼠标按钮、快捷键、真实模型推理及保存结果断言，无需真人在电脑前。它不会上传图像，也不会把测试画作放入正式的 `paintings/`。

`test_mouse_ui.py` 在真实窗口中验证鼠标连续绘画、橡皮擦、撤销/重做、透明 PNG、暂停和退出，并断言摄像头及模型从未被打开。

`test_shapes_ui.py` 通过两个实际窗口验证形状预览/确认/取消、撤销重做、白底和透明 PNG、平滑调整，以及关闭再打开后的设置恢复；使用临时配置，不改动你的个人设置。`test_hand_shapes.py` 使用官方手部图片及空白帧驱动真实模型，验证三种形状的食指预览和抬笔确认，区别于真人摄像头体验测试。

`test_drag_ui.py` 使用可控的 21 点手部坐标驱动实际应用窗口：食指绘制五角星和圆形、捏合移动、释放、重新抓取、防抖、撤销重做及移动后透明导出。摄像头和模型输出被测试夹具替代；它验证输入到对象操作的流程，不代表真人捏合识别率。

`test_time_ui.py` 在实际窗口和生产主循环中用合成单手关键点验证捏合到张开的完整播放、合拢倒放、平移不影响进度、丢失/抖动、重置和模式切换；验证原对象与撤销重做不变，以及原时间轴位置的点击/拖动无效。断言正常模式全程仅创建一次摄像头和模型，无摄像头预览均不创建；不是实体摄像头的手势体验测试。

| EMA / OpenCV 画布绘制 | 迁入 `painter_core.py`，增加浮点平滑、整笔撤销和保存结果检查 |
| `particles.py` | 复用上游粒子结构，接入手指绘画；改为按时间散开渐隐、沿轨迹发射、局部合成，最多 180 个，仅用于实时预览 |

原依赖为 `opencv-python>=4.9,<5.0`、`mediapipe>=0.10.14,<0.11`、`numpy>=1.26,<2.0`。先验证 0.10.21 和 0.10.18，两者 universal2 包内的平台标签实际为 x86_64，导致 Apple Silicon 的 `pip check` 报错；改用仍在上游范围内的 0.10.32 原生 ARM64 包后检查通过，未修改或伪造第三方包元数据。问题记录见 [MediaPipe #6112](https://github.com/google-ai-edge/mediapipe/issues/6112)。

MediaPipe 使用官方 [Hand Landmarker Tasks API](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/python)，模型从官方 Google Storage 地址下载并校验；模型以 CPU delegate 在本机执行。MediaPipe 内部图像预处理可能创建本地 OpenGL 上下文，不涉及任何云端服务。
